## 1. 要点

メール配信サービス Cuenote FC で、ライブラリの脆弱性からサポート・品質管理担当者の認証情報が取られ、不正なプログラムでデータベースからデータが出力された（ユミルリンクの第一報・第二報）。第二報で、出力が確認されたシステムは 49 に、メールアドレスを含む情報は延べ 5,162 万 8,280 件に広がった。16 システムは件数を調査中で、件数は増える可能性がある。

取られたのは、利用企業の担当者ではなく、運営会社の担当者の認証情報だった。第二報によれば、攻撃者はその認証情報で他のシステムへの認証を試み、不正なプログラムを介して他のシステムのデータを参照し、ログイン時のセッション情報を取って不正にログインしていた。不正アクセスが試みられた 81 システムのうち、複数の企業で使う 3 システムに漏えいの痕跡は無く、単一の企業向けの 78 システムのうち 49 で出力が確認された。

<strong>運営会社の担当者の認証情報は、持っているだけで、どの利用企業のどの依頼の作業かが分からないまま、複数のシステムに開きうる。</strong>

## 2. 通った操作

- **通った操作**: 運営会社のサポート・品質管理担当者の認証情報での認証（他のシステムへの認証の試みを含む）と、不正なプログラムによるデータベースからのデータの出力（第一報）。第二報で加わったのは、不正なプログラムを介した他のシステムのデータの参照と、システムのログイン時のセッション情報を取っての不正なログイン（新たに確認された 45 システム・Cuenote FC 44 と Cuenote BASE 1）。
- **受け付けた側に届くもの**: 一般に、正しい認証情報での認証は、正規の担当者の操作として届く。その担当者が、どの利用企業のどの依頼で入ったかは、認証が通ったことからは区別できない。取られたセッション情報でのログインも、正規のログインの続きとして届く。
- **公表されていないこと**: どのライブラリの脆弱性か、侵入が始まった日（公表された時系列は 10 月 16 日の確認から）、担当者の人数と権限、多要素認証の有無。49 システムがどの利用企業のものか。アドレス帳の付属情報の中身（利用企業ごとに違い、調査が済み次第報告するとしている）。重複を除いた人数。

## 3. 実行前の照合

経路を問わず区別できる条件は、運営会社の担当者が利用企業のシステムに入るとき、認証の通過とは別に、その作業が、どの利用企業のどの依頼に基づくかを、入る前に、利用企業の側にある依頼の記録と照合することである。

- **誰が承認を出すか**: 依頼を出す利用企業。作業の依頼を、問い合わせ番号などとともに利用企業の側で出し、期限を区切る。運営会社の担当者の側では作れない形で出す。
- **どこで照合するか**: 利用企業のシステムの認証・認可を受け付ける仕組み。依頼と結びつかない認証は、パスワードが正しくても通さない。通すときも、期限を区切る。
- **何が残るか**: どの依頼で、どの利用企業のシステムに、いつ入ったかの記録。運営会社の記録とは別に、利用企業が後から照合できる形で残す。

検知は働き、ユミルリンクはサーバを切り離し、ほかのシステムから担当者の情報を削除した。それでも、第二報の時点で出力が確認されたシステムは第一報の 5 から 49 に広がっている。同じように、ベンダーの資格情報で顧客のテナントの操作が通った事案に、[ConnectWise のアプリ ID](https://lemma.frame00.com/ja/critical/briefs/069-connectwise-cloud-backup-app-identity-credential-abuse/) がある。069 はアプリが権限を変えた話で、こちらは人の担当者の認証が担当外のシステムへ広がろうとした話である。

## 4. Lemma でできること

**Lemma は、実行前の照合を、運営会社の担当者が利用企業のシステムに入る側に組み込む。** 侵入を見つけるのではなく、届いた認証が、利用企業の依頼に基づくかを、入る前に照合する。

### 注意したい業界・業務

- **業界 · 自治体・公共**: 行政のお知らせや事業者向けのメールマガジンを、外部の配信サービスで送る自治体。委託先の会社が契約していると、配信先のリストがどこにあり、どのプランで動いているかが自治体から見えにくい。
- **業界 · 調達・サプライチェーン**: 会員や顧客へのメールマガジンを、配信の SaaS に預ける企業。配信のために、氏名や社内の識別番号まで連携していることがある。
- **業務 · アカウント・権限の管理**: 自社の配信環境に置かれた運営会社の担当者のアカウントと、管理画面・API の接続元の設定の管理。

### いまの対策と Lemma の違い

今回の経路は、1 列目（運営会社の担当者の認証情報での認証）と、2 列目（不正なプログラムによるデータベースの読み出し）の両方に関わるが、データの出力に認証情報が使われたかは公表されていない。3 列目は、利用企業の側の入口（管理画面と API の接続元）である。

| 対策 | 担当者の認証情報での認証 | データベースの直接の読み出し | 利用企業の側の入口 |
| --- | --- | --- | --- |
| 脆弱性の修正 | 効かない | 一部 | 関係しない |
| 利用企業の多要素認証 | 関係しない | 関係しない | 一部 |
| 管理画面と API の接続元の制限 | 一部 | 関係しない | 一部 |
| 不正アクセスの検知 | 一部 | 一部 | 一部 |
| **Lemma（実行の前の照合）** | 効く | 効かない | 関係しない |

脆弱性の修正は、入口をふさぐが、認証情報を持つ者に許される操作は変えない。利用企業の多要素認証は、取られたのが運営会社の担当者の認証情報だったため、今回の経路には関係しない。第二報によれば、取られたセッション情報でのログインも通っており、これは多要素認証の後の状態を引き継ぐ。接続元の制限は、利用企業の側の入口を狭める（同社は 10 月 18 日に、制限の無かった操作画面と API に接続元の制限を入れた）が、運営会社の担当者の認証まで止まるかは、公表からは分からない。検知は、アクセス記録の上で出力が起きた後に気づいた。

注：Lemma の照合が働くのは、利用企業のシステムの認証・認可を受け付ける仕組みに照合を組み込み、依頼の記録が運営会社とは別に管理されている場合に限る。サーバに不正なプログラムを置かれ、データベースを直接読まれた場合は、この照合を通らずに出力できる。今回の延べ 5,162 万件超の出力を、この仕組みで止められたとは言えない。担当している利用企業の依頼の範囲の中で悪用されれば通る。表は何を照合しているかの比較で、今回の事案で止まったかどうかを示すものではない。Lemma は、侵入を検出・防止するものではない。

### 点検チェックリスト

メール配信など、データを預ける SaaS について、組織で確認する 3 項目

- 管理画面と API の接続元を自社の IP アドレスに絞り、すべて許す設定のままにしていないか。
- 配信先のリストに、配信に要らない項目（氏名・業種・社内の識別番号など）まで入れていないか。
- 事故のときに、自社が影響を受けたかを運営会社から聞ける取り決めがあるか。

## 5. 事実と時系列

- **サービス**: Cuenote FC は、企業や自治体がメールマガジンや案内を一斉に送るためのメール配信サービス。第一報では、利用企業ごとに専用のシステムを用意する「専用 ASP プラン」のうち、ユミルリンクが管理する 5 システムとされた。第二報では、不正アクセスが試みられた 81 システムのうち、単一の企業向けの 49 システムで出力が確認され、複数の企業で使う 3 システムに漏えいの痕跡は無かった。顧客管理システム Cuenote BASE でも、脆弱性により契約者情報（企業名・氏名・電話・メールアドレス）190 件が閲覧できる状態だった。ほかのサービス（SR-S・SMS・Auth・Survey・Push・安否確認）に影響は無いとしている。
- **経路**: ライブラリの脆弱性により、サポート・品質管理担当者のサービスへの認証情報を取得された。不正なプログラムを設置され、データベースからデータを出力された。担当者の認証情報を用いて、ほかのシステムへの認証も試みられた（第一報）。第二報で、不正なプログラムを介した他のシステムのデータの参照と、ログイン時のセッション情報を取っての不正なログインが、新たに 45 システムで確認された。
- **出力された情報**: メールアドレスを含む情報、延べ 5,162 万 8,280 件（第二報・16 システムは調査中）。重複を除いた人数は公表されていない。Cuenote FC に登録される情報は、配信先のメールアドレスと差し込みや抽出のための氏名・都道府県・生年月日などの付属情報（アドレス帳・利用企業ごとに違う）、配信記録、申し込みページやマイページの記録、利用企業の担当者の情報（氏名・メールアドレス・住所・電話番号）。利用企業や自治体の公表では、氏名、法人名、業種、システム内部の識別番号を挙げるものがある。
- **利用企業・自治体の公表**: 大日本印刷（honto）は、メールマガジンの配信を許諾した顧客の氏名、メールアドレス、識別番号が漏えいした可能性があるとの報告を受けた。埼玉県は、委託先の会社が使うメールマガジンで 669 者の情報が流出した可能性があるとした。NTTPC は、影響は確認できていないが可能性は否定できないとした。漏えいは確認されなかったと公表したところもある。
- **ユミルリンクの対応**: 不正アクセスを確認したサーバを直ちにネットワークから切り離し、脆弱性を直すプログラムを作って適用し、ほかのシステムから担当者の情報を削除した。不正なプログラムの常時監視と、操作画面と API（システム連携の窓口）への接続元 IP アドレスの制限を入れた。警視庁、個人情報保護委員会、JIPDEC に届け出て、外部の専門家と詳しく調べている。新たに影響が確認された 42 社には 10 月 26 日 12 時 30 分までに連絡した（第二報）。

### 時系列

- **2026-10-16**: 6 時 49 分、ユミルリンクの担当者が「システム 01」で自身のアカウントの異常に気づく。10 時 10 分、ライブラリの脆弱性による攻撃と特定し、不審な IP アドレスからのアクセスを遮断する。20 時 10 分、Cuenote BASE で他の利用者の情報が閲覧された記録を確認してシステムを止め、20 時 46 分に脆弱性の修正を適用する（第二報）。
- **2026-10-17**: 4 時 43 分、「システム 02」に不正なプログラムが置かれているのを確認してシステムを止める。12 時 58 分、攻撃の手法を特定し、全システムの点検と外部のセキュリティ会社への協力の依頼を始める（第二報）。
- **2026-10-18**: 「システム 03〜05」の不正なプログラムと、「システム 04」へのサポート・品質管理アカウントでの不正なログインを確認してシステムを止め、同アカウントの削除を始める。14 時 15 分、予防のため同じデータセンターの全システムを止め、海外からのアクセスを一時遮断し、制限の無かった操作画面と API に接続元の制限を入れ、20 時 20 分に不正なプログラムの常時監視を立てる（第二報）。14 時 15 分ごろから、山陽新聞社のメールによる速報などが配信できなくなる（山陽新聞社）。
- **2026-10-19**: 警視庁のサイバー事案の窓口と個人情報保護委員会に届け出る。サポートサイトで告知し、17 時 5 分に適時開示で第一報を出す（5 システム・延べ約 900 万件の試算）。19 時 5 分、自社サイトの版に Cuenote FC と専用 ASP プラン 5 システムの記述を足す。
- **2026-10-20**: 予防のため止めていた他のシステムを順に再開し、JIPDEC に届け出る。21 時 29 分、「システム 03」を経由した「システム 08」への不正アクセスを確認する。埼玉県、NTTPC、各地の自治体などが、利用者への影響を公表する。山形県大江町は同日 11 時、流出は確認されなかったと追記する。
- **2026-10-21**: 大日本印刷が、honto の顧客情報が漏えいした可能性を公表する。ユミルリンクは、接続元の制限が無かった Cuenote SR-S のサーバに予防の制限を入れる。
- **2026-10-22**: 全システムのログインと操作の記録をさかのぼる調査を始める。
- **2026-10-25**: 21 時 45 分、新たに 42 システムで不正アクセスとデータの出力の記録を確認し、影響の範囲の調査を始める。

### 公表後の対応

- **ユミルリンク**: 脆弱性の修正、担当者の認証情報の削除、不正なプログラムを検知する体制の整備、認証画面と API への接続元 IP アドレスの制限を再発防止策に挙げた。管理画面と API で、すべての接続元を許す設定は現時点では受け付けないとした。IPA には全容の解明と原因の特定が済み次第届け出る予定とし、漏えいした個人情報が不特定多数に公開された事実と不正利用は確認されていないとした。同社のドメインを使った第三者をかたる迷惑メールが複数確認されているとして注意を呼びかけている。業績への影響は精査中。
- **利用企業・自治体**: 配信を止めて再開したところや、メール配信システムとの連携を切ったところがある。なりすましメールへの注意を呼びかけている。
