## 1. 要点

サイバー攻撃ではない。Excel の一覧から宛名ラベルを作る際に、住棟・号室を誤った部分から取り、そのまま貼り付けた。ラベルは見た目には正しい宛名で、元の一覧と突き合わせなければ誤りは分からない。誤りが分かったのは、受け取った住民の連絡による。<strong>宛名は、発送の前に元の一覧と機械的に照合しなければ、誤りが見た目では分からないまま、そのまま届く。</strong>

## 2. 通った操作

- **通った操作**: Excel の一覧から作った宛名ラベルを貼った、通知の発送。発送した 1,997 通のうち 846 通で宛先が誤っていた（東京都）。
- **受け付けた側に届くもの**: 一般に、ラベルは見た目には正しい宛名として届く。発送の手続きは、そのラベルが元の一覧の行と合っているかを見ない。
- **届いた情報**: 都営住宅の自治会長 770 名の氏名。住所が漏れたとの記載は、公表にない。
- **公表されていないこと**: どの列を取り違えたか、ラベルを元の一覧と照合する手順があったか、二次的な流出や不正利用の有無。

## 3. 実行前の照合

経路を問わず区別できる条件は、宛名ラベルから通知を発送する側が、そのラベルの宛先が元の一覧のどの行に当たるかを、発送の前に、作業者の目とは別の手段で照合することである。

- **誰が承認を出すか**: 宛名を作った作業者とは別の担当者、またはシステム。通知の対象の範囲（どの通知を、どの宛先に送るか）を、あらかじめ決めた一覧で持つ。
- **どこで照合するか**: 発送の直前。ラベルの宛先を元の一覧の行と機械的に突き合わせ、対象の範囲から外れた宛先が無いかを見る。合わないものは発送せず、照合が済むまで止める。
- **何が残るか**: いつ、どの一覧と、どのラベルを突き合わせて通したかの記録。合わなかったものと、その理由。作業者の操作とは別に、後から第三者に示せる形で残す。

検知は働いたが、分かったのは発送の 15 日後だった。同じように、手作業で束ねた ZIP の中身が、送付の前に再確認されなかった事案に、[TOPPAN×損保ジャパン](https://lemma.frame00.com/ja/critical/briefs/151-toppan-sompo-japan-misdirected-zip/)がある。

## 4. Lemma でできること

**Lemma は、実行前の照合を、宛名ラベルから通知を発送する側に組み込む。** 侵入を見つけるのではなく、ラベルの宛先が元の一覧の行と合うかを、発送の前に照合する。

### 注意したい業界・業務

- **業界 · 自治体・公共**: 住民や関係団体への通知を、名簿や一覧から一斉に郵送する自治体や外郭団体。通知には、氏名や役職など、宛先本人以外に見せない情報が載る。
- **業務 · 配信・送付**: 一覧から宛名を作り、封入・貼付して発送する業務。宛名の誤りは、届いた後でなければ表に出ない。

同じ穴は、名簿から郵送物を作る多くの組織にある。差し込み印刷で作る宛名、表計算ソフトの一覧から作るラベル、委託先が作る発送データ。どれも、一覧の参照を一つずらすだけで全件がずれ、作った本人にはもっともらしい宛名に見える。

### いまの対策と Lemma の違い

今回の経路は、一覧から作った宛名ラベルでの発送である。表は、この経路に、各対策がどう働くかを比べる。

| 対策 | 一覧から作った宛名ラベルでの発送 |
| --- | --- |
| 複数の職員による目視チェック（公社の再発防止策） | 一部 |
| 抜き取りでの確認 | 一部 |
| 個人情報の取扱いの研修 | 一部 |
| メールの誤送信防止ツール | 関係しない |
| **Lemma（実行の前の照合）** | 効く |

複数の職員による目視チェックは、誤りに気づく機会を増やすが、何と何を突き合わせたかは記録に残らず、もっともらしい宛名は見落とされうる。抜き取りでの確認は、全件が同じようにずれた場合は見つけやすいが、一部だけずれた場合は、抜き取った中に入らなければ通る。研修は、注意を高めるが、参照の取り違えは、注意していても起きる。メールの誤送信防止ツールは、電子メールの宛先を見るもので、紙の郵送には関係しない。Lemma は、ラベルの宛先を元の一覧の行と、発送の前に、作業者とは別に照合する。

注：Lemma の照合が働くのは、発送の手続きに照合を組み込み、元の一覧が、ラベルを作る作業とは別に管理されている場合に限る。元の一覧そのものが誤っている場合や、照合の後に封入や貼付の段で取り違えた場合は、この照合でも通る。また、全件の照合が済むまで発送を止める運用にすると、発送は遅れる。表は何を照合しているかの比較で、今回の事案で止まったかどうかを示すものではない。Lemma は、侵入を検出・防止するものではない。

### 点検チェックリスト

名簿や一覧から郵送物を作る業務で、組織で確認する 3 項目

- 宛名ラベルや発送データの各行が、元の一覧のどの行から作られたかを、後から辿れるか。
- 発送の前に、作った本人とは別の人か別の手段が、宛名と元の一覧を全件突き合わせているか。合わなければ発送を止められるか。
- 照合したこと、何と何を突き合わせたかが、確認した人の記憶ではなく記録として残っているか。

## 5. 事実と時系列

- **業務**: 都営住宅の維持管理に関する、自治会長宛ての通知の発送。公社は、東京都の政策連携団体として、都営住宅の維持管理業務を受託している。
- **誤送付の内容**: 通知「排水管清掃の申込方法変更のお知らせ」。宛名ラベルが誤り、本来とは別の住棟・号室の住民に届いた。
- **件数**: 発送 1,997 通のうち 846 通が誤り。76 通は返送され、770 通が本来の宛先以外の住民に届いた。
- **含まれる情報**: 都営住宅の自治会長 770 名の氏名。住所が漏れたとの記載は、公表にない。
- **誤りの中身**: Excel の一覧から宛名ラベルを作る際に、住棟・号室を誤った部分から引用した。どの列を取り違えたかは公表されていない。

### 時系列

- **2026-09-28**: 通知を発送。
- **2026-10-13**: 誤配を受けた住民が公社に連絡し、判明。
- **2026-10-16**: 住宅政策本部と公社が公表。

> 本件の事実は、東京都の報道発表に拠る。誤りの具体（どの列を取り違えたか）は「居住する住棟・号室を誤った部分から引用し」という記述にとどまる。発送枚数・誤配数・氏名の件数は公表の値であり、第三者による検証はない。公表されていないことは、対策が無かったことを意味しない。

### 公表後の対応

- **個別の連絡**: 自治会長と、誤配を受けた住民に、個別に連絡して謝罪と説明を行っている。
- **再発防止**: 複数の職員によるチェック体制の強化等。

発送から発覚までは 15 日、発覚から公表までは 3 日である。気づきは送付元ではなく、受け取った側から来ている。
